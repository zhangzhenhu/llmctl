# 报告结构

使用 `docs/reviews/<date>-<scope>/` 下的文件作为工作产物，并在 review 过程中持续更新，不要等到最后一次性整理。

所有分析文本统一使用中文。

## 00-review-scope-and-assumptions.md

用途：

- 固定本次 review 的边界，避免范围漂移
- 记录关键假设和证据来源，避免后续把推断当事实

必须包含：

- review 范围
- 不在范围内的部分
- 静态审查 / 运行时审查说明
- 关键外部依赖
- 需要额外验证的假设

## 01-product-feature-map.md

用途：

- 作为“产品功能设计说明”而不是简单功能树
- 保留功能目标、流程、规则、状态、约束，支撑后续深入审查

每个主功能建议包含：

- 设计目的
- 解决的用户问题
- 入口与触发条件
- 主流程
- 分支流程 / 异常流程 / 恢复路径
- 关键状态与状态转换
- 关键规则与限制
- 关键文案/承诺/用户心智
- 风险点 / 开放问题
- `confirmed` 与 `inferred` 标记

推荐形态：

```md
# 产品功能设计说明

## 1. 首页当前周期卡片
### 1.1 设计目的
### 1.2 用户价值
### 1.3 主流程
### 1.4 关键状态与分支
### 1.5 关键规则
### 1.6 风险与开放问题
```

## 02-technical-feature-map.md

用途：

- 作为“技术设计与实现说明”
- 让模块边界、数据流、职责归属、实现策略可审查

每个主技术区域建议包含：

- 职责
- source of truth
- 上游依赖 / 下游依赖
- 关键模型
- 关键规则 / 策略 / 阈值
- 状态流转 / 生命周期 / 并发约束
- 持久化 / 通知 / 导出 / widget / 外部集成
- 实现策略
- 风险与疑点

推荐形态：

```md
# 技术设计与实现说明

## 1. CycleTrackingStore
### 1.1 职责
### 1.2 真相源与状态边界
### 1.3 依赖关系
### 1.4 持久化策略
### 1.5 归一化与校验规则
### 1.6 生命周期与并发约束
### 1.7 风险与疑点
```

## 03-architecture-and-code-quality-review.md

用途：

- 从架构与代码实现层逐点 review `02`
- 同时覆盖 bug、冗余、边界问题、设计缺陷、注释问题

每个检查项记录：

- 检查目标
- 状态：`finding` / `checked with no finding` / `needs runtime verification` / `needs product decision` / `deferred`
- 类型：`bug` / `logic gap` / `architecture issue` / `redundancy` / `comment gap` / `best-practice gap` / `risk`
- 主题
- 严重级别
- 优先级
- 置信度
- 证据
- 影响
- 本质原因
- 建议方案

## 04-product-and-ux-review.md

用途：

- 从产品逻辑、体验、信任、平台适配层逐点 review `01`

每个检查项记录：

- 检查目标
- 状态
- 主题
- 严重级别
- 优先级
- 置信度
- 证据
- 用户影响
- 建议方案

## 05-cross-cutting-review.md

用途：

- 汇总跨模块、跨层次、系统性问题

建议包含：

- Apple 规范与平台适配
- 无障碍
- 权限与隐私
- 响应性与生命周期
- 注释与文档质量
- 测试性与可验证性
- 共性反模式

## 06-final-report-draft.md

用途：

- 汇总初稿，为最终校验做准备

必须包含：

- review 范围与方法
- 产品设计摘要
- 技术设计摘要
- 覆盖摘要
- 按优先级分组的 findings
- 按主题分组的 findings
- 已检查但未发现问题的重点区域
- 系统性问题总结
- 分阶段整改方案
- 开放问题
- 需要运行时验证的点

## 07-final-report-validation.md

用途：

- 对初稿做二次校验，避免误报、漏报、夸大或归因错误

每个初稿问题至少记录：

- Draft ID
- 校验结果
- 最终主题
- 最终严重级别
- 最终优先级
- 最终阶段
- 修改了什么
- 为什么修改

## 08-final-report.md

用途：

- 最终交付文档

必须包含：

- 执行摘要
- review 范围与方法
- 优先级概览
- 按优先级分组的 findings
- 按主题归纳的问题索引
- 架构层总结
- 产品层总结
- 平台规范/注释/测试性总结
- 已检查但未发现问题的重点区域
- 分阶段整改方案
- 开放问题
- 需要运行时验证的点
